# Labs

Use synthetic data and local execution. Labs demonstrate a narrow mechanism; they are not production systems.

| Lab | Status | Completion evidence |
| --- | --- | --- |
| [Durable action and replay](durable-action.md) | Runnable | A duplicate work item causes only one side effect |
| Harness budgets and tool constraints | Planned | An agent stops on budget and rejects an unapproved tool |
| Retrieval and scoped memory | Planned | Two synthetic users cannot read one another’s private context |
| Evaluation and regression | Planned | A changed configuration is compared with a held-out baseline |
| Outcome and unit economics | Planned | Human review and failed runs are included in cost per accepted case |

Planned labs require a README, canonical capability IDs, prerequisites, synthetic inputs, expected results, tests, cleanup instructions and explicit limitations before being marked runnable.
