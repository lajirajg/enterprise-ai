# Contributing

Start with [resource intake](docs/contributing/resource-intake.md) for a URL, or [setup](docs/contributing/setup.md) for a content change. Preserve canonical IDs and link from specialised views instead of copying definitions. Mark unfinished content explicitly.

Do not submit confidential documents, proprietary assessments, credentials, customer information or copyrighted source copies. A public URL and an original concise explanation are normally enough. No automatic workflow grants approval to publish third-party content.

Before a PR, validate catalogues, regenerate pages, run tests and build MkDocs strictly using the README commands. Keep capabilities in their owning architecture area and explain any proposed taxonomy change in the PR.
